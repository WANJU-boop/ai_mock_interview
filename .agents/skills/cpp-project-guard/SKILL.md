# C++ Project Guard

## 使用场景

当任务涉及 C++ 代码、头文件、源文件、模块边界、依赖管理、日志使用或项目结构时，必须使用本技能。

## 代码可读性

- C++ 代码应适合初学者阅读。
- 优先使用直接、清晰、可解释的实现方式。
- 不要过度使用模板（template）、宏（macro）或复杂继承（complex inheritance）。
- 不要为了未来功能提前设计复杂抽象。
- 类名、函数名、文件名、变量名继续使用英文。
- 代码注释使用英文，并且只在必要时解释不直观的逻辑。

## 文件职责

- 头文件（header file）负责声明接口、类型和轻量常量。
- 源文件（source file）负责实现具体逻辑。
- 保持头文件和源文件职责清楚。
- 避免循环包含（circular include）。
- 能用前置声明（forward declaration）解决时，不要无意义地 include 大量头文件。
- 不要把多个不相关职责塞进同一个类或文件。

## 依赖与安全

- 不要引入复杂依赖（complex dependency）。
- 新依赖必须先说明解决的问题、替代方案和引入成本。
- 不要硬编码 API key、令牌（token）、密码或其他敏感信息（sensitive information）。
- 涉及外部服务时，优先通过配置模块（Config）或环境变量（environment variable）传入敏感信息。

## 日志要求

- 后续模块必须复用已有日志系统（Logger）。
- 不要在业务模块中直接散落使用 `std::cout` 作为长期日志方案。
- 错误、状态变化和关键流程节点应使用日志系统（Logger）记录。
- 日志内容应清晰，但不要记录 API key、用户隐私或敏感数据。

## 项目约束

- 未经用户确认，不修改 C++ 源文件（.cpp）。
- 未经用户确认，不修改 C++ 头文件（.h / .hpp）。
- 未经用户确认，不修改构建配置文件（CMakeLists.txt）。
- 不添加与当前最小任务无关的新功能。
- 不做大规模重构。
